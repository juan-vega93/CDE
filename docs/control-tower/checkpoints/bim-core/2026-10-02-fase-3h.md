## Condición de parada demostrada

Instrucción de Fase 3H: «Si el Property Index no permite distinguir correctamente quantity source/type: DETENTE antes de falsear provenance».

Schema real y código coinciden:

- `bim-schema.sql:129`: property_sets conserva nombre e identidad UUID de consulta; no expressID del IfcElementQuantity ni tipo de set.
- `bim-schema.sql:141`: properties conserva nombre y value_type de almacenamiento (text/number/etc.), no IfcQuantityArea/Volume/Length ni expressID nativo.
- `bim-schema.sql:158`: property_values conserva valores normalizados y unit textual opcional; no origin/source, quantity IDs, relación de asignación, valueField, dimensión ni evidencia de unidad.
- `bim-property-indexer.service.ts:421` / `:450`: addProperty/extractPropertiesFromSets normalizan y deduplican set/name/value. El payload de búsqueda pierde identidad nativa y multiplicidad de observaciones; metadata del elemento solo contiene versión/fuente del indexador.
- `bim-quantity-extraction.ts:106`: el extractor separado sí obtiene source, quantityType, quantitySetLocalId y quantityLocalId correctamente.
- `bim-property-indexer.service.ts:752`: esas QuantityObservations se devuelven en memoria; se persiste authoring y se publica generación, pero no se persisten las observaciones de provenance.
- `bim-index-store.ts:849`: escritura de property_values no transporta esa metadata.

Ejemplo PostgreSQL real: GrossArea/NetArea/ProjectedArea del padre son `value_type=text`, `value_number=null`, `value_json=null`, `unit=null`. El nombre Qto_RoofBaseQuantities es legible, pero por sí solo no certifica origen IFC semántico.

Falta persistir al menos: contexto/revisión y generación; localId dueño; source; clase nativa del set; expressID del set y quantity/property; quantityType/valueField; valor raw y numérico; ocurrencia/identidad de observación sin deduplicar por valor; unidad explícita/ausente con native unit ID y evidencia de unidades de proyecto cuando corresponda; relación de asignación y alcance instance/type. El rol root/child/standalone puede componerse desde Authoring index de la misma revisión, sin duplicar geometría.

No se implementó una tabla parcial que etiquetara Qto por heurística. La persistencia additive/atómica de las observaciones ya extraídas es una posible siguiente fase, no una migración implementada ni una autorización de reindexado.
