- Sets de tipo ya se indexaban antes de instancia; con el límite global podían consumir cupo y desplazar sets de instancia. No había soporte exclusivo de Psets estándar.
- Flattening ahora recorre hojas de complejos. Se mantienen listas/enumeraciones como texto y rangos como texto delimitado. Referencias/objetos sin campo de valor reconocido no se convierten en parámetros escalares.
- Se mantienen exclusión de vacíos y placeholders, trimming y dedup insensible a mayúsculas de set/name/value. Son diferencias contractuales explícitas frente al inspector, que puede mostrar placeholders. Quantity Provenance no usa esta dedup.
- Atributos no se convierten indiscriminadamente en Psets: Name/GlobalId/IfcClass/typeName siguen en columnas existentes; Tag/ObjectType y otros atributos runtime no tienen cobertura universal en el catálogo SQL. No se amplía ese contrato aquí.
- SQL de catálogo exige modelo ready y limita ejemplos de valores por propiedad, no nombres de Psets. Inspector puede obtener filas de un modelo no-ready o usar fallback Fragments. Cache/snapshots/modelos antiguos son causas adicionales posibles del incidente manual, no verificadas en esa sesión.
- Se mantiene BIM_INDEX_SCHEMA_VERSION=5 para no disparar reconstrucciones automáticas. Aplicación hacia adelante; índices anteriores necesitan reindexación controlada.
- Una apertura IFC por procesamiento, mismas lecturas adaptativas existentes y misma extracción 3C; no nueva pasada global. Dedup de flattening pasa a conjunto de claves, con memoria proporcional al número de propiedades y sin copias geométricas.
