## Exact-content IFC and logical selection

`GET /api/documents/content` acquires buffer B once, computes `toBimRevisionId(B)`, builds canonical key from authoritative documentPath and project from its project segment, emits URI-encoded JSON in `X-Bim-Context`, then sends **B**. `Cache-Control: no-store`. No DB latest-revision lookup, alias reconstruction, frontend hash or IFC parse. Historical delivery uses its returned buffer too. FRAG guarded transport unchanged.

CORS exposes only this additional metadata header; asset proxy forwards it. The IFC loader consumes it only on the BFF content path, rejects a mismatched supplied documentPath, loads the exact response arrayBuffer, and returns context after successful load. Initial/incremental canvas registration already retains loader context. Non-BFF URLs and legacy responses do not manufacture context. This authorized content/proxy change does not alter document business workflows or permissions.

5D aggregate adds `selection.version=1`, `groups[{context,authoringElements[{identityKey,memberCount,graphicalLocalIds}]}]`, and `unresolvedEntityCount`. Quantities remain unchanged. One batched query uses the same repeatable-read published snapshot and exact Authoring revision. Existing alias fields only bridge the existing aggregate transport records; they are never runtime identity or revision evidence. Shared member lookup is built once per response; no per-child DB request, geometry serialization or IFC parse. It scans Authoring membership of the requested models; large models increase response/memory cost.

Frontend matches **projectCode + case-sensitive modelKey + revisionId** to exactly one loaded runtime. It unions all Authoring graphical-present IDs and verifies all against runtime geometry availability. Absent/unknown IDs are never graphical targets. Wrong revision, duplicate contexts, unknown membership or unavailable geometry cause explicit failure, not successful partial highlighting or alias fallback for canonical rows. Requests invalidated by model unload/new actions do not apply a late resolved map.

Canonical partida action invokes existing Highlighter with the whole map, then fit; no tree expansion, large-selection truncation, ghost/visibility mutation, showAll, geometry merging or invented primary root. Existing logical click/panel semantics remain unchanged. Legacy raw tables are not converted to logical metering rows in this blocked quantity phase.
